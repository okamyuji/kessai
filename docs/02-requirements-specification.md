# kessai 要件定義書

作成日 2026-08-11 ／ 版 1.0

FR番号は01-requirements-analysisの機能ツリーの葉と1対1対応します。各FRの受け入れ条件は観測可能・機械判定可能な形で書きます。

## 1. 機能要件（FR）

### FR-A1 カード決済の受付

購入者はデモ商品（固定1点、税込金額はDBのシード値）をStripeのトークン化フォームで購入できます。カード番号・セキュリティコードは自社サーバへ到達しません。

受け入れ条件: サンドボックスのテストカードで決済が成立し、アプリのアクセスログ・DBのどこにもカード番号が存在しないこと（`4242`をgrepして0件）。

### FR-A2 オーソリとキャプチャの分離

決済はオーソリ（仮売上）とキャプチャ（売上確定）の2段階で実行できます。管理画面から個別にキャプチャでき、環境変数`CAPTURE_MODE`（`manual`または`auto`、既定`manual`）で自動キャプチャへ切り替えられます。キャプチャは全額のみとし、部分キャプチャ（オーソリ額の一部だけを確定する操作）はスコープ外です。

受け入れ条件: オーソリのみの取引が`authorized`状態で一覧に表示され、キャプチャ操作で`captured`へ遷移すること。

### FR-A3 3Dセキュア

Stripeの3Dセキュア（EMV 3-DS）を有効化し、テストカードで認証チャレンジのフローが動くこと。

受け入れ条件: 3DS必須のテストカード番号で認証画面が表示され、認証完了後に決済が成立すること。

### FR-A4 二重決済防止

同一の購入操作が二重に実行されても請求は1回だけ発生します。冪等性キーはサーバ発行とし、StripeへのAPI呼び出しにも同一キーを引き継ぎます（ADR-0007）。

受け入れ条件: 同一冪等性キーで並行2リクエストを送ると、片方は決済実行、他方は保存済み結果の返却（結果未確定の間は「処理中」を示す409）となり、`payments`行とStripe側の決済がそれぞれ1件であること。

### FR-B1 返金

`captured`の取引に対して全額または一部の返金ができます。返金累計は取引金額を超えられません。

受け入れ条件: 一部返金で`partially_refunded`、全額到達で`refunded`へ遷移し、超過額の返金要求はRFC 9457エラー（ADR-0012）で拒否されること。

### FR-B2 Webhook受信

StripeのWebhookを受信し、署名検証→イベント記録→即時200応答→ワーカーによる非同期処理を行います。同一イベントの再配信は1回として処理します。

受け入れ条件: Stripe CLIの`trigger`で送った同一イベント2回に対し、`webhook_events`行が1件、後続処理の実行が1回であること。署名不正は400で拒否されること。

### FR-C1 取引一覧・検索・詳細

管理画面で取引を状態・期間で絞り込んで一覧表示し、詳細（状態履歴、台帳エントリ、関連イベント）を閲覧できます。

受け入れ条件: 各状態の取引がフィルタで正しく絞り込まれ、詳細画面に状態遷移履歴が時系列で表示されること。

### FR-C2 返金操作画面

管理画面から金額を指定して返金を実行できます。確認モーダルを経由し、操作者と理由を記録します。

受け入れ条件: 返金実行後に監査ログへ操作者ID・金額・理由が記録されること（FR-D5）。

### FR-C3 イベントログ閲覧

Webhookイベント・Outboxイベントの処理状態（未処理・処理済み・失敗・リトライ待ち）を管理画面で閲覧でき、SSEで自動更新されます。

受け入れ条件: 新しいWebhook受信が画面リロードなしで一覧へ反映されること。

### FR-D1 非保持化とSAQ A構成の維持

カード情報を保存・処理・通過させる実装を持ちません。決済ページのスクリプトはCSPとSubresource Integrityで保護します。

受け入れ条件: FR-A1のgrep条件に加え、決済ページのレスポンスヘッダにCSPが存在すること。

### FR-D2 特定商取引法の表示

特定商取引法に基づく表記ページと、最終確認画面での6項目（分量、販売価格と送料、支払の時期と方法、引渡し時期、申込期間の定めがある場合はその旨、申込みの撤回・解除に関する事項）の表示を実装します。

受け入れ条件: 最終確認画面に6項目すべてが表示され、E2Eテストで検証されること。

### FR-D3 管理画面の認証・認可

管理画面はログイン必須とし、パスワードはArgon2idでハッシュ化します（ADR-0014）。未認証アクセスはログイン画面へリダイレクトされます。

受け入れ条件: 未認証で管理画面URLへアクセスすると302でログインへ誘導され、ログイン試行はレート制限されること。

### FR-D4 シークレット管理

StripeのAPIキー・Webhook署名シークレット・DB接続情報は環境変数（`.env`、git管理外）から読み込み、起動時に存在検証します。

受け入れ条件: 必須シークレット欠落時にアプリが起動失敗し、欠けたキー名（値ではない）をエラー表示すること。リポジトリをgitleaksでスキャンして検出0件であること。

### FR-D5 監査証跡

金銭に関わる操作（決済、キャプチャ、返金）と管理画面の操作を、操作者・日時・内容つきで記録します。台帳（ADR-0008）は追記のみで改変できません。

受け入れ条件: 返金操作後、監査ログと台帳エントリの両方から操作を復元できること。

## 2. 非機能要件（NFR）

| 番号 | 要件 | 受け入れ条件 |
|---|---|---|
| NFR-1（整合性） | 決済状態・台帳・Outboxは同一トランザクションで矛盾なくコミットします | 台帳の借方合計=貸方合計の不変条件検証クエリが常に0差分であること |
| NFR-2（耐障害性） | Stripe API障害時もリクエスト受付は継続し、Circuit Breaker（ADR-0010）で遮断・復旧します | Stripeのモックを落とした状態で購入操作がエラー応答（500連鎖でなくRFC 9457）となり、復旧後にOutboxリトライが自動で追いつくこと |
| NFR-3（再送耐性） | すべての非同期処理はat-least-once前提で冪等です | Outboxイベントを人為的に二重実行しても結果が変わらないこと |
| NFR-4（応答性能） | 管理画面の一覧表示はローカル環境・取引1万件で1秒以内に応答します | シードデータ1万件でのアクセスを実測すること |
| NFR-5（セキュリティ） | CSRF対策、セキュリティヘッダ、SQLパラメタライズ、エラーの内部情報非漏洩を実装します | gosecとgitleaksのCI検出が0件、手動のCSRFトークン欠落リクエストが403であること |
| NFR-6（テスト品質） | 変更コードのユニットカバレッジ80%以上、状態遷移テーブルは全セル網羅、主要フローのE2Eを持ちます | CIでカバレッジ閾値を強制すること |
| NFR-7（可読性） | 決済用語・パターンにはコード上のドキュメントコメントで根拠ADRを参照させます | `internal/`配下の各パッケージに`ADR-[0-9]{4}`へのコメント参照が1件以上あることをCIのgrepで検証すること |

## 3. MVP境界

MVPは01の機能ツリーでMVPと記した葉（葉18件のうち拡張候補のA5・B3・B4・C4を除く14件）で、本書のFRはこの14件に対応します。第2段階までを本書のFRが規定し、第3段階（拡張候補）のFRは要件化しません。拡張候補を実装する際は本書へFRを追加してから着手します。

| 段階 | 内容 |
|---|---|
| 第1段階（サンドボックスで決済が1本通る） | FR-A1〜A4、FR-B2、FR-D1・D2・D4 |
| 第2段階（運用できる） | FR-B1、FR-C1〜C3、FR-D3・D5 |
| 第3段階（拡張候補、要件化前） | サブスクリプション、対帳、インボイス、台帳可視化、決済手段追加、CDCリレー |

## 4. 用語集

| 用語 | 定義 |
|---|---|
| PSP | 決済代行サービス。本書ではStripeを指します |
| オーソリ | 与信枠の確保（仮売上）。この時点では請求が確定しません |
| キャプチャ | オーソリ済み金額の売上確定 |
| トークン化 | カード情報をPSPが預かり、代わりに無意味な識別子（トークン）を返す仕組み |
| SAQ A | PCI DSSの自己問診の最簡易区分。カード情報が自社を通らない構成で適用されます |
| 冪等性キー | 同じ操作の再送を1回として扱うための識別子 |
| Outbox | 状態変更とイベント記録を同一トランザクションで書き、別ワーカーが配送するパターン |
| CDC | Change Data Capture。DBの変更ログ（WAL）から変更を捕捉する方式 |
| Circuit Breaker | 外部呼び出しの失敗が続いたら一定時間遮断し、試行的に回復を確認するパターン |
| 複式簿記 | 1取引を借方・貸方の2行1組で記録する台帳方式 |
| SKIP LOCKED | PostgreSQLの`SELECT FOR UPDATE SKIP LOCKED`。他プロセスがロック中の行を飛ばして取得する句で、複数ワーカーのジョブ二重取得を防ぎます |
| ULID | 時系列でソート可能な一意ID。本プロジェクトの主キー生成方式です（ADR-0004） |
