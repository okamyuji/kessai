# ADR-0010 Stripe API呼び出しにCircuit Breakerを適用する

## ステータス

Accepted（2026-08-11）

## コンテキスト

PSPは外部依存であり、障害時に呼び出しを続けるとワーカーのリトライが滞留し、復旧後に負荷が集中します。Zenn記事「Goとsunabarで送金を本番品質にする — Outbox/CircuitBreaker設計」の知見を織り込みます。

## 決定

Stripe API呼び出し（決済実行・キャプチャ・返金）にCircuit Breakerを適用します。Closed→Open→Half-Openの3状態とし、Open中は即座に失敗を返します。Outbox経由の呼び出し（キャプチャ・返金）はイベントを次回実行時刻付きで再スケジュールし、同期呼び出し（PaymentIntent作成）は購入者へ503（`psp-unavailable`）を返します。実装は小さな自前実装（状態遷移テーブル駆動、ADR-0011と同型）とし、外部ライブラリは使いません。

## 根拠

障害の伝播を止めて復旧を早める標準手段であり、状態遷移テーブルの学習素材としても適合します。自前実装は数十行で済み、失敗判定の閾値・回復試行の挙動を学習者が読める形で持てます。

## 影響

失敗率閾値・Open保持時間・Half-Openの試行数を設定値として持ち、管理画面にブレーカー状態を表示します。Webhook受信（Stripe→自社）は自社が呼び出す側ではないため対象外です。

## 検討した代替案

goburrow/breakerやsony/gobreaker等の既存ライブラリは実用上十分ですが、内部状態が学習目的に対してブラックボックスになるため自前実装を選びました。実装が設計から逸脱した場合はライブラリへ切り替えます。
