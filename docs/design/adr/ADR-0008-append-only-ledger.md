# ADR-0008 台帳はappend-onlyの複式簿記とする

## ステータス

Accepted（2026-08-11）

## コンテキスト

決済の記録は監査証跡として改変不能であるべきで、かつ並行更新の競合を最小化したい要件があります。

## 決定

台帳（ledger_entries）は一度書いた行を更新も削除もしないappend-only方式とし、1取引を借方・貸方の2行1組で記録する複式簿記とします。残高はエントリ合計から導出し、残高カラムの直接UPDATEを行いません。

## 根拠

UPDATEを使わないため同一口座への並行更新競合が構造的に減ります。全履歴がそのまま監査証跡（QUALITY_RUBRICの観点、機能要件D5）になります。借方合計と貸方合計の一致という不変条件を機械検証できます。

## 影響

勘定科目（PSP未収金、売上、返金）の最小セットを03-basic-designで定義します。手数料と入金の科目は第3段階の対帳導入時に追加します。エントリはtransfer_id（2行を束ねるID）を持ちます。transfer_idは`{payment_id}:{イベント種別}:{連番}`の決定的導出とし、UNIQUE制約は`(transfer_id, side)`の複合で張ります。これによりOutboxリトライの再実行では同じtransfer_idが導出されて`ON CONFLICT DO NOTHING`で二重記帳を防ぎつつ、借方・貸方の2行1組は共存できます。残高照会が集計クエリになるため、件数増加時はマテリアライズドビュー等を検討します（現段階では実装しません）。

## 検討した代替案

残高UPDATE方式は実装が単純ですが、更新競合と証跡消失のリスクがあり、決済学習の目的に反します。
