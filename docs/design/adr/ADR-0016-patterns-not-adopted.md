# ADR-0016 Sagaとキャッシュ層は現段階で採用しない

## ステータス

Accepted（2026-08-11）

## コンテキスト

Zenn記事群（Saga/Outboxパターン、cache stampede対策）のパターンを本設計へ織り込むにあたり、適用しないものにも理由を記録します。

## 決定

次の2パターンは現段階で採用しません。

1. Sagaパターンは採用しません。Sagaは複数サービス・複数DBにまたがる分散トランザクションの補償手段であり、本構成はモノリス+単一PostgreSQLで、ローカルトランザクションとOutbox（ADR-0009）で整合性を保証できるためです。PSPとの結果整合はOutboxのリトライと冪等性キー（ADR-0007）で担います。
2. キャッシュ層（Redis等）とcache stampede対策は採用しません。MVPの読み取りは管理画面の一覧・詳細のみで、キャッシュが必要な負荷特性を持たないためです。導入する場合の方式（記事で比較した4戦略からの選定）は、負荷を実測してボトルネックを確認してから決めます。

## 根拠

適用条件を満たさないパターンの導入は複雑さだけを増やします。「憶測ではなく実測」の原則に従い、キャッシュは必要性が測定で示されてから入れます。

## 影響

将来サービス分割やキャッシュ導入の要件が出た場合、本ADRをSupersededにして新しいADRを起こします。

## 検討した代替案

学習網羅性のためにSagaを疑似的に組み込む案は、適用条件を偽装する設計になり学習を誤らせるため却下しました。
