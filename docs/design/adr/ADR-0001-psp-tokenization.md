# ADR-0001 決済実現方式は決済代行サービス利用とトークン化とする

## ステータス

Accepted（2026-08-11）

## コンテキスト

日本のEC加盟店は割賦販売法によりカード情報の非保持化（自社の機器・ネットワークで保存・処理・通過させない）またはPCI DSSフル準拠が義務です。本プロジェクトは決済初心者の学習用であり、PCI DSSフル準拠の監査対応は目的に対して過大です。

## 決定

決済代行サービス（PSP）が提供するトークン化JSウィジェットを使い、カード情報を自社サーバに一切通さない構成とします。これによりPCI DSSは最簡易のSAQ A相当になります。

## 根拠

トークン化フォーム構成は非保持化とSAQ Aを同一手段で満たします。PCI DSS v4.0.1で一時SAQ Aに追加されたスクリプト管理要件（6.4.3と11.6.1）は2025年3月31日のPCI SSC更新で除外されています（業界解説記事ベースの確認。導入時はSAQ A最新版を直接確認します）。除外後もCSPとSubresource Integrityによるスクリプト保護は実装します。

## 影響

カード番号・セキュリティコードを扱うコード・DBカラム・ログ出力を作りません。決済フォームはPSPのiframe/ウィジェット埋め込みになります。

## 検討した代替案

自社でのカード情報処理はPCI DSSフル準拠が必要になるため却下しました。リダイレクト型（ホスト型決済ページ）はSAQ A適用では同等ですが、画面の学習範囲が狭くなるためトークン化JS型を選びました。
