# ADR-0005 マイグレーションはgolang-migrateとする

## ステータス

Accepted（2026-08-11）

## コンテキスト

決済台帳のスキーマ変更は事故コストが高く、履歴管理された前進・後退マイグレーションが必要です。候補はgolang-migrate、goose、Atlasです。

## 決定

golang-migrate v4系（2026-08-11時点の最新タグv4.19.1をGitHub APIで実測)を採用します。マイグレーションはdb/migrations/配下の連番SQLファイル（up/downペア）で管理します。

## 根拠

SQLファイルベースで最も普及しており、学習段階ではSQLがそのまま履歴として残る形が最も理解しやすいためです。PostgreSQLのトランザクショナルDDL（ADR-0003）により失敗時は自動ロールバックされます。

## 影響

downマイグレーションも必ず書きます。破壊的変更（カラム削除・型変更）はexpand-contract（追加→移行→削除の3段階）で行う方針を03-basic-designに記載します。

## 検討した代替案

Atlasは宣言的管理とCIでの破壊的変更検知が強力ですが、学習初期には概念が増えすぎます。スキーマ変更が頻繁になった段階で再評価します。gooseはgolang-migrateに対する明確な優位がありません。
