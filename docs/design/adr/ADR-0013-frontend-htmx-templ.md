# ADR-0013 フロントエンドはhtmx 2系とtempl、Tailwind CSSとする

## ステータス

Accepted（2026-08-11）

## コンテキスト

決済フォームと管理画面（取引一覧・返金・Webhookログ）が必要です。開発者はGoエンジニアで、フロントエンド専任はいません。Reactには公式のLTS概念が存在しないことを調査で確認済みです。

## 決定

htmx 2.0系（2026-08-11時点の最新安定タグv2.0.9をGitHub APIで実測。v4.0.0はベータ段階のため採用しません）、テンプレートエンジンはtempl v0.3系（同v0.3.1020）、CSSはTailwind CSS v4系（同v4.3.3）、局所的なクライアント側動作にAlpine.js v3系（同v3.16.0）を採用します。

## 決定の根拠

管理画面はサーバー主導のCRUDと閲覧が中心で、htmxならHTML断片の差し替えだけで実装できます。リアルタイム更新はhtmxのSSE拡張を使います。StripeのトークンJSはフレームワーク非依存で埋め込めるため、この選定はPCI DSS適合に影響しません。templは型安全でGoコードにコンパイルされ、単一言語・単一ツールチェーンを保てます。

## 影響

npmビルドパイプラインを持ちません（TailwindはスタンドアロンCLIを使います）。htmxのDOM差し替え後にStripeウィジェットを再マウントする初期化フックを設けます。SPA的リッチ操作が要件化した時点でReactを再評価します。

## 検討した代替案

React 19 + Vite + TanStack Queryはビルドチェーンとnpmエコシステムの保守負荷が増え、学習の主対象（決済ドメイン）と競合するため見送りました。
